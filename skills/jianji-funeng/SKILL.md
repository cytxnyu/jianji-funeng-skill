# 剪辑赋能skill

把两个品牌组件变成“按内容选择、按原话改字、按语义落点插入”的剪辑工具。显示名称保持 **剪辑赋能skill**；调用标识为 `$jianji-funeng`。

## 交付与素材

- 默认交付 `edit-plan.json`、每个组件的 MP4／末帧图、可编辑 Remotion 工程；有视频且用户要求加到视频时，再交付保留原音轨和总时长的增强版 MP4。
- 输入可以是视频＋SRT、带时间戳文稿，或已有 Remotion 工程。只有无时间轴文稿时先做内容映射，不捏造时间点；需要合成时再取得视频／可靠时间轴。
- 先查看用户素材和现有项目，原视频与安装的 Skill 都作为只读源。复制模板到新的工作目录再修改。
- 默认沿用：标题鎏金 `#D7AF62`、白色 `cyt` 印记；提示词卡标题“提示词”、粉色高亮 `#F276AE`。用户指定的文字、颜色、署名和风格覆盖默认值。

## 内容判断

先读 [内容匹配规则](references/content-matching.md)。把视频中的“章节转折／可照抄的提示词／普通叙述”分开，而不是见到“第一步”或“提示词”就加卡片。

1. 有视频时运行 `scripts/pipeline.py inspect`，读媒体参数、字幕并看抽帧。抽帧只是初筛，候选插入点还要查看前后画面与口播。
2. 按真实语义边界选位置。标题概括紧接着讲的这一段；提示词卡引用用户实际说出、提供或屏幕展示的指令。每次选择留下时间范围和原话证据。
3. 可以一张都不加。无匹配内容、没有章节变化、纯情绪叙述都不硬套。标题不夸大结果，提示词不把模型建议冒充视频原话。
4. 写 `edit-plan.json`，结构见 [计划格式](references/plan-schema.md)。精确时间只来自媒体或字幕。先把所有时间换算到源视频帧率再决定区间，组件之间不重叠。
5. 先校验，再渲染。真实视频里的提示词必须给够阅读时间；2 秒只用于明确要求的外观样片。长内容缩写时保留约束与含义，完整提示词另交文本；需要改写成新指令时明确标成“建议提示词”。

## 执行

具体命令和运行环境见 [运行与验收](references/runtime.md)。工具链：Python 3.10+、Node.js（版本见模板 package.json）、npm、FFmpeg／ffprobe。语义选择由正在执行本 Skill 的 Agent 完成，脚本只负责确定性校验、渲染和合成，不宣称脚本能理解任意视频。

- `pipeline.py init` 复制自带工程；进入新工程执行 `npm ci`。
- `pipeline.py validate --plan PLAN --cues CUES` 检查时间、证据、文字容量、高亮索引和阅读时长。
- `node scripts/render-plan.mjs --plan PLAN --out OUT` 渲染计划中的组件和核对帧。
- `pipeline.py assemble` 将组件覆盖到对应画面区间，原音轨照常继续，片长不增加；如果用户要插入停顿／改变音轨／透明叠加，单独建剪辑方案，不把画面替换误称为这些模式。
- 自带模板是 16:9 横版。其他比例先做该比例原生重排与可读样帧，不拉伸横版套用；当前脚本会拦截未经重排的合成。
- 只有字幕时可交付组件与时间表；只有稿件时交付内容映射和可预览的独立组件，说明还需要真实时间轴才能合成。

## 完成检查

实际解码成片，核对尺寸、帧率、片长、原音轨是否保留，逐张检查入场／高亮／末帧及关键文字。合成后检查每个切入点前后，避免遮挡必须展示的操作。交付成片、计划、可编辑工程与实际验收结果；没有渲染或试听的项目不写成已验证。

只处理用户本轮视频，不自动上传原视频、字幕或剪辑计划，不主动发布任何内容。修改以新产物交付；回退时使用保留的原文件，不删改用户源视频。
