# 内容匹配：先判断它有没有用

## 章节标题

适合：开始一个新阶段、明确切换操作对象、从原因进入方法、从演示进入总结。标题写“接下来做什么”，而非复述上一句。

- 从相邻两段之间找边界，优先在旧动作完成、下一动作开始前的自然间隙。
- 标题通常 1–2 行，每行 6–14 个汉字；复杂术语可以保留，不机械删掉关键限定。
- 默认 2–3 秒。仅在需要时增加 Part 编号；编号跟随该视频已有结构，从现有序列续排。
- 署名默认白色 cyt；英文副标题可留空，别为了填模板编造术语。
- 反例：“第一步我其实做错了”是叙述而非新步骤；“大家先看一下”没有新章节，不自动加标题。

## 提示词卡

适合：视频正在教观众向 AI 输入什么，屏幕出现可复制指令，或用户明确要求把一段要求整理成提示词。

- 区分“提到提示词”与“给出提示词”。“提示词很重要”没有可展示的指令，应跳过。
- 卡片先保留任务、对象、输出格式和关键约束，再删口头填充词。
- 内容 1–5 行。粉色只高亮决定结果的那一行，例如目标、输出结构或关键限制；不默认永远高亮第三行。
- 每张卡标记来源时间和原文。摘要与原文有变化时在计划 reason 中说明，别标成逐字引用。
- 没有现成指令时不代用户补一段假原话。若用户要求新拟提示词，caption 用“建议提示词”，把创作依据写入 reason。
- 阅读时间初检：不少于 3 秒，且约 `1.5 + 字符折算数 / 9` 秒；ASCII 按半字折算。这是排版启发式，最终仍以实际阅读为准。窗口太短就缩短、拆卡或换位置，不延长视频来偷空间。

## 画面和节奏

- 先记证据：原话、时间、对应画面，再决定 component 与 props。不要先分配一堆槽位再硬找内容。
- 同一语义只表达一次。标题后紧跟重复相同信息的提示词卡，通常删掉其中一个。
- 两个全屏组件不重叠；不覆盖必须看清的按钮操作、输入反馈、结果对照。画面正是证据时，优先把卡放在口播解释段。
- 若全文没有合适内容，输出空 segments 与跳过原因。不要把数量当验收指标。
- 候选点检查前后至少一句口播和约 1 秒画面；有歧义时按用户原意保守处理。
